# Локальный тестовый научный каталог NeSToR

**Назначение: только локальное тестирование.** Каталог не является научным справочником
NeSToR, не публикуется, не подключается к облаку и не попадает в git
(`var/test_catalog/`, `var/` в `.gitignore`). Публикационная сборка не создаётся.
Право на повторное использование ни одного источника не подтверждено; включение всех
научных неперсональных записей, в том числе со статусом «не проверено» и «исключён»,
разрешено заказчиком только для локального тестирования.

Сводка без записей: [TEST_CATALOG_SUMMARY.json](TEST_CATALOG_SUMMARY.json).
Сборка: `nestor_app/test_catalog.py`, `tools/build_test_catalog.py`.

## Правила объединения

* Строки **не объединяются по совпадению гаплотипов**: каждая первичная запись источника —
  отдельная запись каталога.
* Дубли копирования снимаются только на уровне **источника целиком**: общие источники
  Purps 2014 (`Scientific_Purps2014_PPY23` = `purps2014`) и NIST 1032
  (`Scientific_NIST1032_UAS24` = `nist2022`) сравниваются по опубликованным значениям
  всех записей. Совпали полностью → берётся копия архива (подробнее происхождение: файл,
  лист, строка, QC-статусы), копия кандидата не добавляется. Если бы копии различались,
  остались бы обе с пометкой.
* Коллизии ID источника сохраняются как отдельные записи с флагом «коллизия ID».
* `user_scientific_since_20261008` — агрегированные наблюдения гаплотипа с числом N из
  источника; у каждой — ссылка на публикацию (как записана) и флаг «возможное
  пересечение публикаций», если в том же снимке есть индивидуальная запись того же
  источника с тем же гаплотипом. Пересечения только помечаются, записи не удаляются.
* У каждой записи: источник, публикация, ID образца, файл / лист / строка, шкала аллелей,
  лицензия (как в метаданных), статус проверки и пометка
  «локальное тестирование; право на повторное использование не подтверждено».
* Значения: исходные — дословно (`raw_markers_json`); позиции для сравнения — отдельно
  (`positions_json`): корректные — числа, `not_read` — нет значения, прочие QC-статусы и
  нечисловые значения — «не распознано» (в GD не входят).

## Поиск и пометки

* Каталог выключен по умолчанию; `build` его не включает, `build-release --enable` (и
  сценарий `Build-TestCatalog.ps1`) — включает после всех проверок. Состояние на главной
  странице: «Научный тестовый каталог: включён / выключен» с числом записей.
* Включённый каталог показывается **отдельным разделом** результатов (гостевой поиск и
  поиск владельца): «Научный тестовый каталог» с меткой «ЛОКАЛЬНОЕ ТЕСТИРОВАНИЕ» и баннером о
  непроверенных данных, в той же таблице, что и на странице `/compare`. У каждой строки — вид
  записи (индивидуальная / агрегированная, N — гаплотипы с численностью, не отдельные люди;
  итог найденного отдельно по индивидуальным записям и агрегатам с суммой N), «GD (предварительно)»
  (шкалы источников не откалиброваны, T15) и статус проверки. Лицензия (как в источнике), качество
  (позиции, не вошедшие в сравнение, с QC-статусом источника), пометка о праве на повторное
  использование и флаги — в раскрытии «Источник»; различия по локусам — в раскрытии «Различия».
* Вкладки результатов каталога — по числу реально сравненных позиций: Все · 12–16 · 17–27 · 28–37 · 38 и больше;
  открывается самая глубокая вкладка с результатами. Панели FTDNA и Генопоиска здесь не подходят: полных Y37 и длиннее
  в каталоге 85 записей (один источник), полных панелей Генопоиска нет. Вкладки по панелям — только у поиска по профилям.
* Шкала Y-GATA-H4: значения в каталоге образуют два пика (11–12 и 20–21) с провалом на 17, значения от 18
  есть у 845 записей (Underhill 2010 — все 277 с этим локусом; ещё `user_scientific_since_20261008`, `maniot2026`,
  одна запись Ballantyne 2014). Если профиль и запись оказались по разные стороны порога 18, строка получает метку
  «другая шкала H4?», а в раскрытии «Различия» — пояснение; записи, не прошедшие условия только из-за этого локуса,
  считаются над таблицей. Значения и GD не пересчитываются (T15). Для Underhill 2010 сравнение с ближайшими
  R1a-соседями (`r1a2015`, Balanovsky 2011) даёт разницу +9 в 90% пар, но первичного основания для поправки нет.
* Каталог не смешивается с пользовательскими профилями и не влияет на гостевую выборку 20%.
* Выключение и удаление действуют без перезапуска: флаг проверяется при каждом запросе.

## Проверка форматов (синтетические файлы, tests/fixtures/formats)

`tests/test_formats.py`: FTDNA Y12 / Y25 / Y37 / Y67 / Y111 и Genopoisk Y37 / Y50 в
CSV (`;` и `,`), TSV, XLSX и вставленной таблице — распознавание и выбор панели,
точные значения, число позиций и аллелей (12 / 25 / 37 / 67 / 111; Genopoisk Y37 — 36,
Y50 — 52 значения по составу архива); пользовательские наборы на 18 и 50 значений с
явными заголовками (панель не распознаётся); отказ для строки значений без заголовков
(состав по числу значений не угадывается, в том числе при выбранной панели); пропуски
(пусто, «0», «-»), дроби (T18), копии в колонках a/b/c/d и разное число копий (T17),
DYS389 (T16: II − I и опубликованный DYS389B), нераспознанные значения; сравнение GD 0 / 1
/ 2, межпанельное пересечение и поиск по синтетическому тестовому каталогу.

## Команды

### Сборка на своём компьютере (Windows, обычная учётная запись)

Нужны два исходных файла: `Genopoisk_expert_linux_2026-10-14.tar.gz` (или `.zip`, внутри
которого лежит этот `.tar.gz`; если у вас только части `.tar.part1–5.rar` — сначала
распакуйте их 7-Zip / WinRAR) и `Nestor_scientific_YSTR.db`. Права администратора и сеть
не нужны. В PowerShell из папки `nestor` (пути замените на свои):

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools\Build-TestCatalog.ps1 -Release "C:\Data\Genopoisk_expert_linux_2026-10-14.tar.gz" -Candidate "C:\Data\Nestor_scientific_YSTR.db"
```

Что делает команда (код возврата 0 — только если всё прошло):

1. `Get-FileHash`: архив `745ca9cd…d9b5`, кандидат `c6f713b1…7d7d` (SHA256SUMS.txt);
2. извлекает только `reference/scientific.sqlite` во временный файл в `var\test_catalog`
   и проверяет его SHA-256 `98a99416…be9e`; временный файл удаляется;
3. собирает каталог во временную базу и сверяет количества: 60 011 записей,
   51 985 индивидуальных, 8 026 агрегированных (сумма N = 8 612), 33 источника,
   20 662 снятых дубля; при расхождении прежний каталог и флаг не меняются;
4. включает каталог и проверяет его в локальном интерфейсе отдельными запусками
   `run_nestor.py`: каталог виден (раздел «ЛОКАЛЬНОЕ ТЕСТИРОВАНИЕ», агрегаты с N) →
   после перезапуска по-прежнему включён → после `disable` не виден → снова включён;
5. отчёт без записей — `var\test_catalog\BUILD_REPORT.json` (SHA-256 входов,
   количества, статусы источников, `catalog_content_sha256`; эталон сборки
   `4ba60e29…4f36` — сверка содержимого, не зависит от версии SQLite).

Выключить или удалить (состояние хранится в `var\test_catalog\ENABLED` и переживает
перезапуск NeSToR):

```powershell
py -3 tools\build_test_catalog.py disable
```

```powershell
py -3 tools\build_test_catalog.py remove
```

```

```

(физическое стирание с SSD не гарантируется).
