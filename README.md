# GENOPOISK CRM

Локальное Windows-приложение для учёта ДНК-тестов, заказов, лабораторных
этапов, сроков, результатов и клиентской выдачи. Реализовано строго по
технической спецификации (ТЗ v1.0).

Статус: ядро (этапы 1–5 из раздела 26 ТЗ) реализовано и протестировано —
**62/62 автотеста проходят**, см. [`ACCEPTANCE_REPORT.md`](ACCEPTANCE_REPORT.md).
Telegram-интеграция (этап 6) готова как парсер, но без подключённого Bot
Token. Сборка Windows EXE (этап 7) настроена через GitHub Actions и
провалидирована сборкой под Linux в среде разработки — финальная проверка
на Windows произойдёт при первом запуске workflow.

## Список реализованных функций

- **База данных**: SQLite со схемой из раздела 2 ТЗ (заказы, тесты, услуга
  «Отчёт» без GNPSK, справочники типов тестов/доставки/операторов,
  product_mappings, audit log, счётчик GNPSK, настройки, ошибки импорта).
  Версионирование схемы через `schema_version` — задел на будущие миграции.
- **Бизнес-логика**: расчёт дедлайна (раздел 7), цветовая логика с приоритетом
  зелёный > красный > пурпурный > жёлтый > обычный (раздел 8), транзакционная
  генерация номеров GNPSK (раздел 4), разбор заказа на несколько тестов
  (раздел 5), запрет отчёта для WGS.
- **Заказ ↔ тесты**: заказ и тест — разные сущности; один заказ → несколько
  тестов с независимыми GNPSK, датами, статусами, результатами.
- **Аудит**: все существенные изменения (тип, комплектация, даты, результаты,
  статус, финансы) пишутся в `audit_log` со старым/новым значением; ничего не
  удаляется физически — только логическое архивирование.
- **Excel-импорт**: предпросмотр (всего строк / сопоставление колонок),
  импорт с сохранением исторических номеров без перенумерации, дубли по GNS
  пропускаются, ошибочные строки уходят в `import_errors` и не теряются,
  исходный файл не изменяется.
- **Backup/Restore**: ручной и (раз в сутки) автоматический backup через
  SQLite backup API, хранение N последних копий, обязательный pre-restore
  backup перед восстановлением.
- **Telegram-парсер** (без сетевого клиента): извлечение номера заказа,
  товарных позиций, суммы, статуса оплаты, способа/адреса доставки, ФИО,
  email, телефона, кодов платежа/заявки/блока, формы; разворачивание
  комплектов (напр. FULL LINE) через `product_mappings`; создание заказа со
  статусом «Требует проверки» при нераспознанном товаре; обновление (не
  дублирование) существующего заказа по повторному сообщению.
- **Локальное хранилище секретов**: Telegram Bot Token хранится отдельно от
  БД и исходного кода, в защищённом каталоге профиля пользователя.
- **UI (PySide6)**: компактный список тестов (10+ строк без прокрутки на
  экране ноутбука) + компактная карточка выбранного теста, полная форма
  редактирования отдельным диалогом, поиск и быстрые фильтры, диалоги нового
  заказа/импорта/backup/настроек.
- **Telegram-приём заказов**: long-polling через `app/telegram_client.py` (тонкий клиент
  на stdlib, без внешних зависимостей) и `app/telegram_poller.py` (фоновый QThread).
  Настраивается на вкладке «Telegram» в Настройках: ввод токена, кнопка «Проверить
  подключение» (вызывает `getMe`), галочка «принимать автоматически при запуске».
  Токен никогда не покидает `secrets_store.py` за пределами сетевого вызова.
- **UI для product_mappings**: диалог «Товары (Telegram)» на панели инструментов —
  добавление/редактирование/удаление сопоставлений «название товара → типы теста»
  без правки кода.
- **Экспорт в Excel**: кнопка «Экспорт в Excel» на панели инструментов, учитывает
  текущий поиск/фильтр главного экрана.
- **История изменений заказа**: кнопка «История изменений» в карточке теста — единая
  хронологическая лента audit_log по заказу и всем его тестам.
- **Настройки**: стартовый номер GNPSK, порог «приближается дедлайн»,
  папка/количество резервных копий, справочник операторов, Telegram Bot Token и
  режим автоматического приёма.

## Инструкция сборки (Windows EXE)

### Автоматически через GitHub Actions (рекомендуется)

1. Создайте приватный репозиторий на GitHub, запушьте туда содержимое этой
   папки (БД, backups и любые файлы с реальными клиентскими данными в
   репозиторий **не** попадают — их там просто нет, `.gitignore` это
   гарантирует).
2. Любой push в `main`, тег `v*`, или ручной запуск
   **Actions → Build Windows installer → Run workflow** запустит сборку на
   `windows-latest`:
   - установка зависимостей, прогон 62 автотестов;
   - сборка onedir-бандла через PyInstaller;
   - smoke-test — запуск собранного EXE с проверкой, что он не падает сразу;
   - сборка `GENOPOISK_CRM_Setup.exe` через Inno Setup 6 (уже на раннере);
   - публикация артефактов `GENOPOISK_CRM-Setup` (инсталлятор) и
     `GENOPOISK_CRM-portable` (папка для диагностики без установки).
3. Скачайте `GENOPOISK_CRM_Setup.exe` из вкладки Actions → конкретный запуск
   → Artifacts.

### Вручную на Windows-машине

См. подробности в [`packaging/BUILD.md`](packaging/BUILD.md). Кратко:

```powershell
python -m venv venv
venv\Scripts\activate
pip install -r requirements.txt
python -m pytest tests\ -v
pyinstaller packaging\genopoisk_crm.spec --distpath dist --workpath build --noconfirm
"C:\Program Files (x86)\Inno Setup 6\ISCC.exe" packaging\installer.iss
```

Готовый инсталлятор: `dist_installer\GENOPOISK_CRM_Setup.exe`.
Портативная версия для диагностики: папка `dist\GENOPOISK_CRM\`.

**Важно:** проверьте запуск на чистой Windows-машине без установленного
Python/PySide6 перед выдачей пользователю — PyInstaller-сборка включает всё
необходимое, но финальная проверка на «чистой» машине ещё не проводилась
(среда разработки — Linux, физически не может это подтвердить).

## Инструкция установки

1. Скачайте `GENOPOISK_CRM_Setup.exe`.
2. Запустите — мастер установки предложит выбрать каталог (по умолчанию
   `Program Files\GENOPOISK CRM`, можно изменить) и создать ярлык на рабочем
   столе.
3. После установки приложение запускается сразу, без установки Python/Node.js
   или других зависимостей.
4. При первом запуске автоматически создаётся база данных в
   `%APPDATA%\GENOPOISK_CRM\data\genopoisk.db` — **не** внутри каталога
   установки, так что удаление программы не затронет данные.
5. Удаление программы (через «Установка и удаление программ») удаляет только
   файлы приложения — база, резервные копии и настройки в `%APPDATA%`
   остаются нетронутыми.

## Инструкция backup/restore

- **Ручной backup**: кнопка «Резервные копии» на панели инструментов →
  «Создать резервную копию сейчас». Файл сохраняется в выбранную папку с
  именем `genopoisk_ГГГГ-ММ-ДД_ЧЧ-ММ-СС.db`.
- **Автоматический backup**: раз в сутки при наличии изменений, если папка
  резервных копий задана в Настройках → «Резервные копии».
- **Хранение**: настраиваемое количество последних копий (по умолчанию 30);
  старые копии сверх лимита удаляются автоматически.
- **Облачная синхронизация**: можно указать папку внутри OneDrive/Google
  Drive/Dropbox/Яндекс.Диска — синхронизацию обеспечивает клиент облака,
  приложение просто пишет файлы в обычную папку на диске.
- **Восстановление**: «Резервные копии» → выбрать копию из списка →
  «Восстановить из выбранной копии…». Перед восстановлением **автоматически**
  создаётся резервная копия текущей (в том числе испорченной) базы — ничего
  не теряется безвозвратно. После восстановления приложение нужно перезапустить.

## Инструкция импорта Excel

1. Панель инструментов → «Импорт Excel» → «Выбрать файл Excel…».
2. Приложение автоматически сопоставит колонки файла с внутренними полями
   (GNS, № заказа, ФИО, тип теста, даты и т.д.) по распространённым
   заголовкам и покажет предпросмотр (первые строки + количество строк).
   Если колонка с GNS/GNPSK не найдена — импорт заблокирован до исправления
   файла (без номера тест невозможно однозначно идентифицировать).
3. Нажмите «Импортировать». После завершения показывается статистика:
   импортировано / пропущено дублей / ошибок / всего строк, плюс список
   первых ошибок.
4. Строки с одинаковым GNS, который уже есть в базе, считаются дублями и
   пропускаются (повторный импорт того же файла безопасен — не создаёт
   дублей и не меняет номера).
5. Строки без GNS или с другими проблемами не импортируются, но и не
   теряются — они сохраняются в таблицу `import_errors` для последующего
   разбора.
6. Исходный Excel-файл никогда не изменяется.

⚠️ Реальный файл пользователя ещё не был прогнан через импортёр — сделайте
это после получения файла и сверьтесь со статистикой предпросмотра/импорта
перед тем, как полагаться на результат в рабочем процессе.

## Инструкция подключения Telegram

1. Настройки → вкладка «Telegram» → вставить Bot Token → «Проверить подключение»
   (должно показать `✓ Подключение успешно: @имя_бота`).
2. Поставить галочку «Автоматически принимать заказы из Telegram при запуске
   программы» → «Сохранить».
3. Приём работает, пока программа открыта (long-polling, без необходимости в
   публичном webhook-адресе). Новые заказы появляются в основном списке
   автоматически, статус-бар показывает сводку по каждой партии сообщений.
4. Заполните справочник товаров: панель инструментов → «Товары (Telegram)» →
   добавьте точные названия товаров сайта и соответствующие им типы тестов
   (раздел 28 ТЗ). Без этого нераспознанные товары будут помечаться «Требует
   проверки» — это ожидаемо и безопасно, не угадывание.
5. Токен хранится **только** в `%APPDATA%\GENOPOISK_CRM\secrets\secrets.json` —
   вне БД, вне исходного кода, вне резервных копий БД.

**Реальный Bot Token ещё не был предоставлен и не подключался** — весь код
проверен на сохранённых тестовых сообщениях и заглушенной сети (см.
`tests/test_telegram_poller.py`, 10 тестов). Первое реальное подключение
нужно проверить на живом токене.
