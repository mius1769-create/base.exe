# GENOPOISK CRM — Release 1.1

Ветка `claude/haplogroup-color-logic-o5yk0q`, 9 коммитов поверх `main`
(последний смёрженный релиз на `main` — вкладка «Гаплогруппы», условно
Release 1.0). Ветка ещё не запушена в `origin` (доступ на запись не
выдан) — этот документ фиксирует, что войдёт в 1.1, когда push пройдёт.

Полный список коммитов: `git log origin/main..HEAD --oneline`.

---

## 1. Вкладка «Гаплогруппы» — доработки по итогам ревью

*(коммиты `623a61c`, `655a1e8`, `c31b18a`, `301d019`)*

- Цветовая логика переработана: GREEN/RED/NONE по совпадению **крупной
  гаплогруппы** (ведущая буква корня первого токена NevGen/Semargl), без
  попыток анализировать филогению субкладов (CRM не имеет доступа к
  дереву YFull/ISOGG, поэтому сравнение конкретных SNP на вложенность
  признано ненадёжным и убрано).
- Поле **Y-ДНК** блокируется (read-only, серым) для тестов мтДНК
  (`МитоДНК Базовый`, `Полный митогеном`) — на уровне UI и дополнительно
  на уровне репозитория (`haplogroups_repo.upsert_haplogroup`
  принудительно обнуляет `y_dna` при каждом сохранении для этих типов).
- Починен рендеринг цвета строк: правило `QTableWidget::item` в
  `theme.py` заставляло Qt игнорировать `setBackground()` — добавлен
  собственный `QStyledItemDelegate`, красящий фон вручную.
- Починена гонка инициализации диалога редактирования записи и защита от
  потери привязки к архивному тесту.

## 2. Автосоздание записи гаплогруппы для новых тестов

*(коммит `6ab5180`)*

- **Причина бага**: `list_haplogroups()` строит выборку `FROM
  haplogroups` (не `LEFT JOIN` от `tests`) — до этого коммита ни одно из
  трёх мест создания `tests` (`repository.py`, `importer.py`,
  `historical_import.py`) не писало в `haplogroups`, поэтому новый тест
  физически не мог там появиться.
- `repository.ensure_haplogroup_stub(conn, test_number, full_name)` —
  `INSERT OR IGNORE`, вызывается сразу после `INSERT INTO tests` в той
  же транзакции, во всех трёх местах.
- Идемпотентная миграция в `db.py` (`_migrate_missing_haplogroup_stubs`)
  на каждом старте досоздаёт записи для уже существующих тестов, у
  которых их не было (исторический импорт, тесты, созданные до этого
  коммита).

## 3. Архивирование заказов (каскадное)

*(коммит `72e1ef3`)*

- `repository.archive_order()` теперь каскадно архивирует заказ → все
  его тесты (`tests.order_id`) → все связанные записи гаплогрупп
  (`haplogroups.test_number`), с отдельной записью в `audit_log` на
  каждую затронутую строку. Идемпотентно — повторный вызов не дублирует
  аудит и не трогает уже архивированные строки.
- Кнопка **«Архивировать заказ»** в карточке «Внутренней работы», с
  подтверждением «Архивировать заказ и все связанные данные?».
- Чекбокс **«Показывать архив»** (по умолчанию выключен) на всех трёх
  вкладках («Клиентская», «Внутренняя работа», «Гаплогруппы») —
  архивные строки при включении показываются серым текстом.
- Все три вкладки обновляются мгновенно (`refresh_all()`), без
  перезапуска и без переключения вкладок.

## 4. Вкладка «Дашборд» (первая слева)

*(коммиты `5744db2`, `6bf0c34`, `ee1c31b`)*

Новая первая вкладка, три независимые подвкладки.

### Финансы
- KPI: выручка месяца, себестоимость месяца, валовая прибыль,
  маржинальность, средний чек.
- Блок **«Прогноз месяца»**: план / факт / прогноз (`факт / прошедшие_дни
  × дней_в_месяце`) / выполнение плана %.
- Таблица **«Экономика по типам тестов»**: тип, продано, цена,
  себестоимость, выручка, прибыль.
- Кнопка **«Настроить цены»** — редактор `price`/`cost_price` по каждому
  типу теста.

### Статистика
- KPI: заказов за месяц, тестов за месяц, выдано результатов, новых
  клиентов (уникальных `customer_name`).
- Горизонтальный bar-chart «Продажи по типам тестов».
- Таблица **«Среднее время выполнения»**: тип / среднее / медиана / мин
  / макс (только завершённые тесты, `client_issued_at − created_at`).
- Блок **«План / факт»** с прогресс-барами (заказы/тесты/выдачи), кнопка
  «Настроить план».

### Операционка
- KPI: в работе, в лаборатории, готово к выдаче, просрочено.
- Производственная воронка (6 стадий, горизонтальные прогресс-бары).
- Таблица просроченных тестов (тип, клиент, дней просрочки — от самой
  большой просрочки), двойной клик открывает тест.
- **«Зависшие тесты»** — топ-10 самых старых незавершённых, двойной клик
  открывает тест.
- **«Последние события»** — из `test_events` (маршрут теста) + отдельно
  архивирование заказа из `audit_log` (архивирование — операция над
  заказом, в `test_events` её нет).

### Схема БД для дашборда
- `test_types` получил `price REAL`, `cost_price REAL` (идемпотентная
  `ALTER TABLE` миграция для уже существующих БД).
- Новая таблица `dashboard_targets` (`year, month, target_orders,
  target_tests, target_issued, target_revenue`, PK `(year, month)`).
  Первая версия миграции ошибочно создавала другую форму таблицы (`month
  TEXT PK`) — исправлено пересозданием при обнаружении старой схемы;
  `target_revenue` в уже правильную форму добавляется обычным `ALTER
  TABLE` без потери введённых планов.

## Известные ограничения / зафиксированные допущения

Чтобы не всплывали как «баги» через неделю — эти решения приняты
осознанно и задокументированы в коде:

- **Выручка «Финансов»** (`orders.order_amount` за месяц) и **«Экономика
  по типам тестов»** (продано × `test_types.price`) — два разных числа,
  не обязаны совпадать 1:1: один заказ может включать несколько типов
  тестов, а цены на отдельный тест внутри заказа в БД нет.
- **«Готово к выдаче»** в воронке = `lab_profile_received_at` заполнено
  И `client_issued_at` пусто — отдельного поля для этого статуса в БД
  нет.
- **«В лаборатории»** (Операционка, KPI) = `lab_sent_at` заполнено И
  `lab_profile_received_at` пусто.
- **«Среднее время выполнения»** считается по **всем** завершённым
  тестам (не ограничено выбранным в «Статистике» месяцем) — иначе по
  многим типам тестов за один месяц набиралось бы слишком мало данных.

## Не проверено на реальной сборке

- Windows-сборка PyInstaller с новым модулем `QtCharts` — этот
  Linux-контейнер не может собрать `.exe`; сам факт, что `QtCharts`
  ставится вместе с уже закреплённым `PySide6==6.11.1` (тянет
  `PySide6-Addons`), проверен, но живого прогона собранного EXE на
  Windows не было.
- Дашборд и архивирование не покрыты выделенным набором `pytest` —
  проверялись через живые скрипты на настоящем `MainWindow`/`QApplication`
  (описаны в истории коммитов), а не через `tests/`.

## Push

Ветка не запушена в `origin` — `git push` стабильно возвращает `403`
(нет прав на запись у этой сессии). Все файлы переданы пользователю
напрямую по мере готовности каждого коммита.
