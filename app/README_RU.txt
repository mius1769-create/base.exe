GENOPOISK CRM — итерация Dashboard / Promo / Operational

В эту итерацию входят:
1. Промо-заказ: чекбокс «Промо-заказ (бартер / реклама)» при создании заказа.
2. Существующие БД автоматически получают orders.is_promo INTEGER DEFAULT 0.
3. Промо исключается из коммерческой финансовой аналитики: выручка, средний чек, себестоимость, прибыль, маржинальность, продажи и новые клиенты.
4. Промо остаётся в операционной нагрузке и производственной воронке.
5. В финансах показывается отдельный блок стоимости промо по каталожному прайсу.
6. Экономика по тестам использует фактическую сумму заказа, распределённую между тестами заказа пропорционально каталожным ценам.
7. Статистика: динамика коммерческой выручки — LINE; структура выручки — DONUT.
8. Финансы: структура коммерческой выручки — DONUT.
9. Операционная аналитика: только с 01.08.2026; старые записи не удаляются.
10. Операционные KPI, воронка, просрочки, зависшие тесты и последние события используют чистый период с 01.08.2026.
11. Отрицательные сроки выполнения исключены из среднего времени.
12. «Внутренняя работа» и основной маршрут тестов не менялись.
13. Архивирование отменённых заказов сохраняется; архивные заказы не участвуют в Dashboard.

Файлы для замены в D:\Base\base.exe\app\:
- dashboard_repo.py
- dashboard_stats_tab.py
- dashboard_finance_tab.py
- repository.py
- new_order_dialog.py

Опционально можно оставить dashboard_ops_tab.py из архива — он не требует изменений в этой итерации.

ПЕРЕД ЗАМЕНОЙ:
Сделайте копию текущих пяти файлов.

ПОСЛЕ ЗАМЕНЫ:
1. Запустите из корня проекта:
   python -m py_compile app\dashboard_repo.py app\dashboard_stats_tab.py app\dashboard_finance_tab.py app\repository.py app\new_order_dialog.py
2. Затем запустите CRM из Python/текущего способа запуска и проверьте Dashboard.
3. Только после проверки пересоберите EXE существующим spec-файлом.

ВАЖНО:
Миграция is_promo выполняется автоматически при первом обращении Dashboard или при открытии «Новый заказ». Значения старых заказов получают 0.
